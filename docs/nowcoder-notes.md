# 牛客「网申助手」插件调研与借鉴

来源：<https://www.nowcoder.com/my/resume-plugin-intro>（2026-10-28 抓取，V1.1.2，2026-10-22 发布）

## 它是什么

牛客网的浏览器插件（Chrome / Edge），面向校招/社招的「AI 网申一键填写」：

- 用户先在一处**结构化填写一次简历/网申信息**
- 插件在招聘官网页面**智能识别表单字段并自动填写**
- 支持「批量投递百家名企」，宣称已适配约 **90% 主流招聘官网**
- 「智能学习填写习惯」，用得越多填得越准
- 提供**报错反馈**入口，用户遇到未适配网站可上报，官方优先修复

## 对我们有借鉴意义的点

1. **结构化档案是一等公民**
   它把「姓名/手机/邮箱/教育/经历/项目」等拆成结构化字段，而不是一段自由文本。我们目前只有 AI 技能介绍和图片简历，做任意网申前必须补一个结构化档案表单（name/phone/email/city/education/work history 等），并支持从 PDF 简历解析预填。

2. **字段映射是独立一层**
   「AI 识别字段」本质是：抓取 label/placeholder/name/id → 映射到档案字段。应做成确定性字典优先（姓名/手机/邮箱/学校/专业/起止时间等常见词表），模型兜底处理未知字段。这样便宜、稳定、可解释。

3. **站点适配/配方（recipe）**
   宣称适配 90% 官网，说明纯模型并不够，背后有站点级规则。我们的对应方案：第一次成功填写后把「域名 → 字段选择器/操作序列」存成 recipe；同站下次直接回放，模型只在异常时介入。

4. **填写习惯学习**
   用户纠正过的字段（例如某站点把「期望城市」叫「意向工作地」）应写回该域名的映射表，越用越准。

5. **反馈闭环**
   记录失败站点、失败字段、截图，形成待适配列表；这比让 agent 每次硬试更可持续。

6. **预填 + 一键填写分离**
   预填发生在产品内（用户专注完善资料），一键填写发生在目标网站（轻量、快）。我们对应：资料面板 + agent 浏览器工具分离。

## 与我们的差异

- 它是**浏览器插件**：运行在用户自己的浏览器里，天然复用登录态，验证码/短信由用户当场处理。
- 我们是**服务端 per-user runner**：需要 VNC 接管来把验证码/登录交还用户；好处是能服务器端批量执行、统一调度、不依赖用户开着浏览器。

## 落地到我们的路线

- P1：结构化档案 + 字段映射字典 + 浏览器工具（open/snapshot/fill/click/upload）
- P2：域名 recipe 缓存与纠错写回；失败反馈记录
- P3：从 PDF 简历自动抽取档案字段；批量网申队列
